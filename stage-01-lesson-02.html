01 / A USEFUL MODEL

A computer is a state-changing machine.

At first, computers seem impossibly complicated because modern machines contain billions of transistors and layers of software. But you do not need billions of details in your head. You need a model that explains the important relationships.

FIRST MENTAL MODEL

A computer stores information as state, reads instructions that describe operations, transforms that state, and communicates results through input/output devices.

INPUT

Information enters the system.

STATE

Information exists somewhere.

COMPUTE

Instructions transform it.

OUTPUT

The result becomes observable.

This model is intentionally broad. A keyboard press, a network packet, a value in RAM, a CPU register, and a pixel on screen all become pieces of a causal chain.

The key relationship is that the CPU needs instructions and data. Those values must come from somewhere, and their changes must be stored somewhere. That is why memory becomes central to systems programming.

03 / STATE + INSTRUCTIONS

Programs cause state to change.

Imagine a tiny machine with one register named R0 and two locations in memory. The instruction LOAD R0, [1000] means: copy the value stored at memory address 1000 into register R0.

WHY REGISTERS?

Registers are tiny, very fast storage locations inside the CPU. The processor uses them while executing instructions. You will meet them again when we reach assembly and computer architecture.

PREDICT / 02

Memory address 1000 contains 7. R0 contains 0. After LOAD R0, [1000], what should R0 contain?

05 / WHERE THE OS FITS

So why do we need an operating system?

If every program could directly control all memory, storage, network hardware, and devices whenever it wanted, programs would constantly collide with one another. Modern operating systems provide controlled abstractions over these resources.

RESOURCE MODELAPPLICATION → KERNEL → HARDWARE
PROGRAM

“I need memory.”

KERNEL

Coordinates and protects resources.

MEMORY

Physical hardware resource.

RESULT

Program receives a usable abstraction.

The kernel is not merely “another app.” It runs with special privileges and mediates access to critical machine resources. That boundary is one of the central ideas you will keep descending toward.

06 / CHECKPOINT

Can you explain the machine without the vocabulary fog?

By the end of Lesson 02, you should be able to explain:
  • a computer as a system that stores and transforms state;
  • the basic roles of CPU, memory, storage, and input/output;
  • why CPU registers and memory both hold state but serve different roles;
  • how an instruction can cause state to change;
  • why an operating system coordinates access to hardware resources.
