HOW KERNEL PATH WORKS

Less watching. More doing.

Kernel Path is designed around causal understanding. The learner sees the system, predicts what will happen, tests it, and explains the result.

Learning loop

  • See a visual mental model
  • Predict what the machine will do
  • Run or inspect the system
  • Break something intentionally
  • Debug the result
  • Explain why it happened

Paid workshop layer

The roadmap can stay free while deeper labs become premium products. The first planned workshop is Systems Lab 01: Memory, covering pointers, addresses, stack, heap, allocation, memory bugs, and GDB.

PROJECT CHECKPOINTS

Prove it by building it.

The goal is not to collect concepts. Each major stage should produce something you can run, inspect, explain, and eventually show.

Mini Shell

Processes, fork/exec, pipes, signals, file descriptors, and command execution.

Memory Allocator

Manual allocation, free lists, fragmentation, addresses, and debugging.

Tiny Filesystem

Blocks, metadata, persistence, paths, and storage structures.

Your Own Kernel

Boot, memory, interrupts, scheduling, and eventually user space.
