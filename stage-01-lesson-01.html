01 / WHY GO LOWER?

Your program is the top of a very deep stack.

Most programming begins with an abstraction: write some code, press Run, and something happens. That is useful, but it hides the machinery responsible for making the program exist.

Low-level development asks a different kind of question. Instead of only asking “What does this code do?”, we also ask “What has to happen inside the computer for this code to do it?”

THE SYSTEMS QUESTION

When something happens on screen, trace backward. Which program caused it? Which operating-system service did the program need? What state changed in memory? What instructions did the CPU execute?

This is the habit Kernel Path will build. You are learning to move through layers without treating the layers below you as magic.

02 / THE ABSTRACTION STACK

Meet the layers between you and the silicon.

A computer can be understood as a stack of cooperating abstractions. Each layer makes the layer below it easier to use.

03 / SYSTEMS THINKING

Start predicting what must be true.

You do not need to know every implementation detail yet. Instead, practice reasoning from effects back toward causes.

PREDICT / 01

You double-click an executable and the program begins running. Which statement is the best first mental model?

That distinction between an executable and a process becomes extremely important later. A file on disk is not the same thing as a running program.

04 / YOUR FIRST EXPERIMENT

One tiny program. Many hidden layers.

You do not need to run this yet. First, look at the program and make a prediction about what the computer must do.

// hello.c
#include <stdio.h>

int main(void) {
  printf("Hello, machine!\\n");
  return 0;
}
THINK BEFORE RUNNINGYOUR MODEL

What do you think has to happen between this file and “Hello, machine!” appearing on screen?

There is no penalty for being wrong. Write your current model; later you can compare it with what you learn.

05 / CHECKPOINT

What should you know before moving on?

By the end of Lesson 01, you should be able to explain:
  • why low-level development requires looking beneath application code;
  • the rough relationship between source code, executable, process, operating system, and hardware;
  • why an executable file and a running process are not the same thing;
  • why Kernel Path asks you to predict before you run.

Lesson 01 complete?

Mark it complete when you can explain the abstraction stack without looking. Next, we make the model more concrete: CPU, memory, instructions, and state.
