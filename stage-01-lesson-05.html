01 / THE PROGRAM

Start with one boring little file.

Create a file named memory_lab.c. The program is intentionally tiny so the interesting part is not application logic. The interesting part is what you can observe around it.

memory_lab.cSTAGE 01 / LAB
// memory_lab.c #include <stdio.h> int main(void) { int x = 7; int *p = &x; printf("x = %d\\n", x); printf("&x = %p\\n", (void*)&x); printf("p = %p\\n", (void*)p); printf("*p = %d\\n", *p); *p = 42; printf("x now = %d\\n", x); return 0; }
BEFORE RUNNING

Predict two things: should &x and p print the same address? And after *p = 42, what should x print?

Two observations matter more than the exact hexadecimal address: p contains the same address produced by &x, and assigning through *p changes the object x.

04 / STEP WITH GDB

Pause execution and look inside.

Compile with -g, then launch gdb ./memory_lab. The simulator below demonstrates the sequence conceptually.

On your own machine, useful commands include break main, run, next, print x, print &x, and print p. Later you will use GDB to inspect much harder failures.

05 / PREDICT

Reason before changing the program.

PREDICT / 05

Suppose you change int *p = &x; to int *p = NULL; and still execute *p = 42;. What is the best expectation?

06 / CHECKPOINT

You have now interrogated a real program.

Before Lesson 06, you should be able to:
  • compile a small C program with debugging information;
  • run the resulting executable;
  • print a variable's value and address;
  • show that a pointer can contain that address;
  • modify a variable through a dereferenced pointer;
  • use basic GDB commands to pause and inspect execution;
  • separate an observation from an assumption about how the machine works.

One lesson left in Foundations.

Lesson 06 is the checkpoint: you will explain the full path from source code to process, memory, kernel, and CPU without leaning on the diagrams.
