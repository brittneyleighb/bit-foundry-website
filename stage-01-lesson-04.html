Not Magic.

Variables do not float in a conceptual cloud. While a program runs, data occupies storage that the program can refer to through addresses. Pointers make that relationship explicit.

01 / WHERE VALUES LIVE

A variable has a value, but the value must exist somewhere.

Consider int x = 7;. At the language level, x is a named object with an integer value. During execution, the program needs some storage for that object. We can refer to its location using an address.

MENTAL MODEL

A variable name is useful to the programmer. An address identifies a location in the program's address space. A value is the data represented in storage at that location.

The exact physical story is more complicated because modern systems use virtual memory. For now, think in terms of addresses visible to the process. We will deliberately refine that model later.

02 / ADDRESSES

Give the bytes a location.

Imagine our program sees x at address 0x1000. The address is not the integer 7. It tells us where the storage associated with x begins in this simplified model.

int x = 7;
int y = 12;

printf("%p", (void*)&x);
printf("%d", x);

These addresses are illustrative. Real addresses vary between runs and systems, and an int's size is implementation-dependent, though four bytes is common on modern platforms.

03 / POINTERS

A pointer is a value that represents an address.

In C, &x asks for the address of x. A pointer can store that address. Dereferencing the pointer with *p accesses the object it points to.

p contains 0x1000, the address of x.

Notice what changes when you set *p = 42. You are not changing the address stored in p; you are changing the value in the object reached through that address.

04 / STACK + HEAP

Not all program memory is used the same way.

A process's virtual address space is organized into regions with different purposes. Two names you will encounter constantly are the stack and heap.
